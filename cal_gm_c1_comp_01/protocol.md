# CAL-GM-C1-COMP-01

把 C1-01 Direct 里混在一起的三件事拆开。不用 C1-01 冻结题，不用含糊的 `conflict` 字段。

## 组件 A：初始冲突检测

输入两个 Agent 最初选择的资源与时段。只输出：

```json
{"initial_conflict_detected": true}
```

Oracle：同一资源且同一时段为 true，否则 false。冲突发生在调整前的初始方案。

## 组件 B：最终方案是否无冲突

给出已经形成的最终分配。只输出：

```json
{"final_plan_conflict_free": true}
```

Oracle：最终方案没有重复占用为 true，仍有重复占用为 false。Scorer 根据给出的最终分配自己计算，不把模型布尔当事实。

## 组件 C：知道冲突后重新分配

明确告诉模型初始方案存在冲突，以及：

```text
高优先级 Agent 保留原时段；
低优先级 Agent 使用最早可行空闲时段。
```

只交 `assignments`，禁止输出任何冲突布尔。

## 解释

| 检测组件 | 分配组件 | 结论 |
| --- | --- | --- |
| 失败 | 通过 | 会安排，但不会稳定表达或识别初始冲突 |
| 通过 | 失败 | 能发现冲突，但不会按规则形成新方案 |
| 两者都通过 | C1-01 失败 | 单组件会做，完整上下文再次发生接口集成退化 |
| 两者都失败 | Direct 真实能力地板，暂时停止 C1 | |
| 两者都通过 | 可以建立 C1-02 | |
