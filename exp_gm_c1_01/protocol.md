# EXP-GM-C1-01

集体协调。两个执行者各持私有约束，彼此不能直接读取；一个协调者按登记规则生成唯一联合方案。重点不是口头“已达成一致”，而是最终世界状态中没有两个 Agent 占用同一资源。

## 题目

| 题目 | 共同资源 | control | intervention |
| --- | --- | --- | --- |
| 充电时段 | 同一充电桩同一时段只能一辆车 | 首选不冲突 | B 的首选改为与 A 冲突 |
| 设备预约 | 同一设备同一时段只能一人 | 首选不冲突 | B 改为争用 A 的设备时段 |
| 装卸口 | 一个装卸口不能同时服务两辆车 | 窗口充足、首选不冲突 | B 的可用窗口缩短并与 A 冲突 |

唯一解决规则：

```text
优先级高的 Agent 保留原时段（若可行且空闲）；
优先级低的 Agent 使用最早可行空闲替代时段。
```

A 优先级高于 B。intervention 只改 B 的一条预登记私有约束。

## 轨道

| 轨道 | 信息 |
| --- | --- |
| Direct | 一次调用看到双方约束，确认固定模型会做这些题 |
| Single-global | 同一 Agent 看到双方约束并制定联合方案 |
| Multi | 两人各持私有约束，经协调者形成方案 |
| Drop | Agent 和协调者都运行，但 B 的约束消息被丢弃 |

## 事件链

```text
任务开始
→ 两个执行者读取各自私有约束
→ 分别发送可行集合和首选方案
→ 协调者收集已送达报告
→ 检测是否存在资源冲突
→ 按登记规则生成联合分配
→ 两个执行者确认
→ 联合方案提交
→ 两个执行者按方案占用资源
→ Scorer 检查最终世界状态
```

通道只允许保存 → 传输 → 读取。不改写报告或方案。环境不改世界状态。Oracle 不进提示。

## 顺序

```text
Rule 正负控 → 冻结 → Direct 6 格 → 可做后再跑 repeat 0 的 18 格
→ R0 有效且不共地板、不共天花板，才考虑补 repeat 1/2
```
