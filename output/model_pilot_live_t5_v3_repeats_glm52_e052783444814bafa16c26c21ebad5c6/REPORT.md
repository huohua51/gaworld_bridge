## Interpretation

The v2 failure was generated by an ambiguous Prompt containing two fields named
`required_action`: the resident-level field said `keep_current`, while the
nested notice field named the global policy action. V3 removes that collision
and passes twice on every registered cell. This supports the narrow conclusion
that the explicit resident eligibility-scope contract is functional and
repeatable for these three task surfaces with GLM-5.2.

## Claim boundary

The task surfaces were reused after diagnosing v2, so this is development
regression evidence rather than a fresh holdout. V2 seed 0 is not combined with
v3 repeats because their Prompt protocols differ. The result does not establish
fresh-task generalization, cross-model stability, human validity, real-world
policy effects or leaderboard performance.
