# EXP-HF-H1H4-02 内部试采运行清单

## 当前状态

内部试采尚未执行，`PILOT_PLAN.yaml`状态为`planned_not_run`。现有`EXP-HF-H1-01`网页不能直接承担本试采：它是固定顺序、单表单、代码/JSON为主的旧版管线，不具备本版本所需的三角色远程状态机和开放消息日志。

因此当前可以做的是：

1. 按`COGNITIVE_INTERVIEW.md`完成5–8人的角色说明访谈；
2. 用各任务`scoring.yaml`做离线正负控Rule校准；
3. 建成并测试v2远程系统后，运行Wave 1的4个三人团队；
4. C1或等价协调路径通过后，再运行共同排序Wave 2的2个团队。

不得手工把访谈记录拼成团队轨迹，也不得把旧H1网页收集的数据改名为v2内部试采。

## 1. 试采前放行

主持人与技术管理员分别签核：

- [ ] 认知访谈门已通过，所有材料版本和修改理由已登记；
- [ ] 目标任务卡、角色说明、评分规则、H4 Codebook和显示规则均记录Git提交或哈希；
- [ ] 每个会话由三个一次性角色令牌进入，令牌无法串用；
- [ ] 每个角色只能看到`visible_bindings`，无法请求`hidden_bindings`；
- [ ] A/B条件名和Human/Agent来源不出现在参与者或评委页面；
- [ ] 事件由服务器赋时、追加保存，重复提交幂等且不能静默覆盖；
- [ ] 退出、超时、断线恢复和管理员操作均有可审计事件；
- [ ] 原始数据目录不在公开Git仓库，身份映射单独受控保存；
- [ ] 对应任务的功能正控和每类负控均产生预期评分；
- [ ] 共同排序Wave 2额外满足C1依赖和合法未达成一致路径测试。

任一项未通过，不创建真人会话。

## 2. 招募与分配

Wave 1使用12人组成4个真实三人团队，每队完成2条轨迹；Wave 2在依赖通过后使用另外6人组成2队。优先避免使用参加过认知访谈的人；无法避免时登记重叠，不能把熟悉任务的人当成全新独立样本。

管理员使用`PILOT_PLAN.yaml`中的固定分配。参与者只知道自己的匿名团队码和角色令牌，不知道条件、来源或另一条件的内容。同一团队内固定角色还是轮换角色必须在开跑前统一决定并登记；本轮建议固定角色，减少学习和身份切换混淆。

## 3. 会话开场

主持人逐字说明：

> 这是系统与说明的内部试用，不是能力考试，也不是正式研究结果。请只通过页面交流，不要用微信、面对面提示或共享屏幕。不要输入姓名、学校、学号或联系方式。你可以随时退出；遇到页面问题请只报告现象，主持人不会告诉你任务答案。

三人分别完成角色知识检查后才能进入任务。任何人两次仍未通过时，结束该条试采并记录`pre_task_comprehension_fail`，不得由主持人讲完答案后继续并记为正常轨迹。

## 4. 运行中主持规则

主持人可以：

- 处理登录、断线、页面无法提交等技术问题；
- 重读公开说明；
- 提醒参与者只使用页面交流；
- 记录时间、错误码和协议偏离。

主持人不可以：

- 说明哪个来源可信、哪个事实应修改、谁应接替或哪种排序更好；
- 解释其他角色能看到的私有内容；
- 建议参与者多发言、同意、反对或提出澄清；
- 替参与者输入消息或重新表述任务答案；
- 因为结果不正确而要求重做。

若主持人提供了任何任务内容提示，该会话标为R0无效并保留原因。

## 5. 每条轨迹现场检查

开始前：

- [ ] 三个角色由不同匿名参与者承担；
- [ ] 条件由服务器分配，参与者页面不显示A/B；
- [ ] 三个角色看到的公开事实、时间预算和动作空间与冻结版本一致；
- [ ] 不存在同一参与者此前接触过该表面另一条件的记录。

运行中：

- [ ] 所有业务消息都经中央会话记录，没有线下沟通；
- [ ] 页面只在状态机允许时释放下一阶段和私有材料；
- [ ] 刷新、重复提交和断线没有生成重复业务动作；
- [ ] 超时、退出、错误和主持人介入均产生事件。

结束后：

- [ ] 会话明确为完成、合法未达成一致、超时、退出或技术失败之一；
- [ ] 原始事件数与页面显示消息/动作数可核对；
- [ ] 功能Oracle输出分子、分母和R0状态，不产生H分；
- [ ] H1匿名刺激不含功能分、条件、来源、内部代号和原始服务器时间；
- [ ] H4机会和事件来自日志，不从最终正确答案倒推；
- [ ] 同一会话无法再次写入或覆盖。

## 6. 当日复盘

每队完成后立即做10–15分钟简短复盘，但不要现场修改正在运行的材料版本：

1. 哪条说明导致等待、越界或重复劳动？
2. 哪个页面状态让你不知道下一步由谁做？
3. 你是否想绕过页面联系队友？为什么？
4. 哪些消息机会看起来人为，哪些像真实协作？
5. 你能否从页面风格猜测未来匿名轨迹的来源？

问题先进入偏离/问题登记表。当天同一波次使用同一冻结版本；需要修改时关闭当前波次，生成新版本后重新试采。

## 7. Wave 1停止与修订条件

出现以下任一情况立即停止新增会话：

- 私有卡、来源、条件或身份代号泄漏；
- 角色令牌串用或未授权动作被服务器接受；
- 事件丢失、乱序到无法恢复、重复计分或静默覆盖；
- Human与预定Agent协议的事实、预算、动作或停止条件无法保持一致；
- 两名盲编码员无法根据Codebook稳定识别核心机会/事件；
- 多数参与者无法在不接受答案提示的情况下完成角色流程。

普通功能错误、合理异议、较慢完成或合法未达成一致本身不是停止原因。

## 8. 试采收口

只生成聚合诊断报告：招募/退出数、R0分母、完成与解析率、每项功能与H4指标的分子分母、编码一致性、用时分布、盲化问题和修订决定。原始消息和身份映射不推送公开Git。

试采只能决定任务、系统、Codebook和预计样本量是否需要修改。完成Wave 1或Wave 2均不自动解除`formal_data_collection_allowed=false`；仍需功效分析、伦理与治理确认、Human–Agent协议等价审计以及正式冻结。
