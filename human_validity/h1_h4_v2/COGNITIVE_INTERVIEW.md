# EXP-HF-H1H4-02 认知访谈脚本（草案）

## 1. 用途与边界

本访谈只检查角色说明、信息边界、任务词语、预期动作和H1盲评问题是否容易理解。访谈数据不是Human Reference，不估计Human–Agent差异，不用于修改GAWorld核心，也不进入正式结果。

- 目标：5–8名年满18岁、能阅读中文且近期有小组项目经验的高校学生。
- 建议使用6人，每人检查两个不同任务族的角色卡，覆盖全部12张角色卡。
- 只记录匿名访谈代号；禁止记录姓名、学号、电话、邮箱、学校或录音中的身份信息。
- 共同排序只做离线说明理解和规则推演；C1或等价协调路径校准通过前不进行实时多人试采。
- 参与者不得接触同一任务表面的A/B两个条件，也不得查看未分配角色的私有内容。

## 2. 建议分配

| 代号 | 第一张角色卡 | 第二张角色卡 |
| --- | --- | --- |
| CI01 | 修订：起草人 | 核验：核验员 |
| CI02 | 修订：审核员 | 交接：第二执行者 |
| CI03 | 修订：发布人 | 排序：安全与照顾代表 |
| CI04 | 核验：信息整理员 | 交接：协调员 |
| CI05 | 核验：决策协调员 | 排序：执行代表 |
| CI06 | 交接：第一执行者 | 排序：协调记录员 |

若只有5人，可让一人检查三张不同任务族的角色卡；若有7–8人，用额外参与者复查访谈中误解最多的角色卡。不要为了凑数让同一个人看同一表面的两个条件。

## 3. 主持人开场白

请逐字读出：

> 我们正在检查一组多人协作任务的说明是否容易理解，而不是考察你的能力。请只根据你看到的页面思考，可以随时说出哪里不清楚。你可以停止参加，也可以跳过不想回答的问题。我们只记录匿名代号和你对说明的反馈，不记录姓名、学校或联系方式。今天的材料不会作为正式实验结果。

确认参与者理解并同意后，记录：`consent=yes`、访谈代号、开始时间和材料版本。若不同意，立即结束，不保存行为内容。

## 4. 每张角色卡的访谈顺序

### 4.1 静默阅读

向参与者只展示其分配角色的共同说明、角色说明和一个任务表面；隐藏条件名、来源、功能答案、其他角色私有卡和后台字段。记录阅读开始与结束时间，不催促。

### 4.2 不提示复述

依次问：

1. 请用自己的话说说团队最终要完成什么。
2. 你这个角色首先要做什么，之后可以做什么？
3. 页面允许你看到哪些信息？明确不允许你看到哪些信息？
4. 什么情况下你应该向别人提问？请举一个具体问题。
5. 什么情况下你的工作算结束？
6. 如果你不确定答案，你会怎么处理？

主持人只追问“你是从哪句话理解到的”，不解释正确答案。先记录参与者原始理解，再进行知识检查。

### 4.3 角色知识检查

使用对应`participant_instructions.yaml`中的`pre_task_comprehension`题目。第一次回答错误时，只说“请再读一次说明”，不得指出正确句子；第二次仍错误则标记`comprehension_fail`，再向参与者解释规则并询问哪处文字导致误解。解释后的操作不得作为无提示成功。

### 4.4 微型情境推演

给出一条不包含正确答案的中间消息，请参与者口头说明下一步会做什么、会给谁发什么消息，以及哪些动作不应该做。不得要求参与者完成整条正式任务。

中性提示仅限：

- “你现在还缺什么信息？”
- “这条消息具体指向哪个事实或步骤？”
- “这是硬约束、软偏好，还是尚未核验的信息？”
- “页面是否允许你的角色执行这个动作？”

禁止提示：

- 指出正确来源、正确改动、正确接替者或最优方案；
- 暗示A/B条件或Human/Agent来源；
- 替参与者补全角色消息；
- 用“你应该……”纠正后再把该题记为成功。

## 5. 各任务族专项追问

### 修订

1. “公开基线标准”和“当前授权标准”是否容易混淆？
2. 审核员怎样写意见才算具体，而不是直接代写最终成品？
3. 发布人能否从共享审核消息判断每项改动的依据？
4. 哪句话可能诱导起草人猜测私有标准？

### 核验

1. “整理两个报告”“判断可信来源”“选择行动”这三步是否分得开？
2. 核验消息中的来源、状态、时间和目录版本分别有什么作用？
3. 协调员看不到私有目录时，是否仍知道如何做决定？
4. 哪种页面布局会让人误以为传闻已经核验？

### 交接

1. “提交检查点”“平台封存”“协调员交接”三个事件顺序是否清楚？
2. 原执行者继续和第二执行者接替时，哪些规则相同、哪些不同？
3. 接替者如何知道从哪里继续而不返工？
4. 哪句话可能让协调员误以为自己应该执行具体步骤？

### 共同排序

1. 参与者能否区分公共硬约束、私有硬约束和软偏好？
2. 成员能否用自己的话表达私有要求而不展示私有卡？
3. “合法未达成一致”是否被误解为任务失败或可以不投票？
4. 协调员如何避免把沉默写成同意？

## 6. H1盲评材料认知检查

执行角色访谈后，向参与者展示一条不含来源、条件名、功能分和内部代号的示例轨迹，并检查候选量表：

1. 请解释“自然”“主动性”“社会回应性”“角色连续性”各自指什么。
2. 哪些问题无法仅根据轨迹判断？缺少什么可观察信息？
3. 哪些题目看起来在重复问同一件事？
4. 你是否不自觉地把“答案正确”当成“像真人”？为什么？
5. 你能否从格式、用词、长度或错误情况猜测来源？信心是多少？
6. 1分、4分和7分分别代表怎样的可观察表现？

主持人不得询问“哪一来源更好”，也不得透露示例来源。功能错误可以保留在刺激中，但评分页面不显示功能分。

## 7. 结束问题

1. 今天最难理解的三个词或句子是什么？
2. 哪一步最容易越过自己的角色边界？
3. 哪一步最像真实小组合作，哪一步最像填表？为什么？
4. 如果在自己电脑上远程完成，你最担心什么？
5. 页面需要增加什么提示，又有哪些提示会泄露答案？

最后提醒参与者不要向后续参与者透露任务内容或条件。

每张角色卡保存一条匿名记录：

记录文件放在公开Git仓库之外。仓库只登记空模板、聚合问题和修订决定，不提交原始访谈文本或身份映射。

## 9. 从访谈进入内部试采的门

必须同时满足：

- 至少5人完成，建议6人；全部12张角色卡至少被无提示复述一次；
- 没有角色说明系统性诱导读取私有信息或替别人执行；
- 每张角色卡的两个知识检查题均至少有一名参与者首次或重读后答对；
- 所有`comprehension_fail`和高频含糊词都有保留证据的修订决定；
- H1评委能用可观察行为解释量表，不把功能正确性直接等同于自然度；
- 修订后的角色说明、评分规则、展示规则和访谈版本重新哈希。

任何私有信息泄漏、来源泄漏或主持人不得不反复给出正确动作都属于停止项。修订后重新访谈，不把失败记录删除后冒充通过。
