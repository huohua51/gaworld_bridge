# H1 Human Trace 试采清单（2026-08-27）

## 1. 本轮目标和边界

本轮只验证采集页面、角色说明、匿名化、保存约束和盲评量表是否可用，不估计 H1 分数，不替代正式 Human Reference，也不把试采数据并入冻结输出。

- 只在本机 `127.0.0.1` 运行；不向公网开放。
- 使用单独的试采输出目录；不要直接写入 `output/exp_hf_h1_01_20260825`。
- 只填写团队、会话、参与者和评委代号；禁止记录姓名、联系方式或其他敏感信息。
- 页面试用可选“单人试采”；正式 Human Trace 必须由三名参与者分别承担角色。
- 每个槽位默认只能保存一次。页面误操作或协议偏离写入偏离记录，不静默覆盖。
- 所有保存的评分都标记为 `pilot: true`，H1 正式分保持 `N/A`。

## 2. 启动隔离试采实验室

在干净工作区中运行：

```powershell
$env:PYTHONPATH = 'F:\proj\gaworld_eval_bridge;F:\proj\GAWorld'

F:\proj\.venv_gaworld_eval\Scripts\python.exe `
  -m exp_hf_h1_01.serve `
  --out output\exp_hf_h1_01_pilot_sandbox_20260827 `
  --port 8765
```

打开：

- `http://127.0.0.1:8765/human.html`：Human Trace 试采；
- `http://127.0.0.1:8765/viewer.html`：匿名刺激复核；
- `http://127.0.0.1:8765/rater.html`：量表试评。

启动时应显示 18 条 Agent 匿名刺激和 0/18 条 Human Trace。若源实验文件缺失、为空或哈希异常，应停止，不得用损坏的刺激继续试采。

## 3. 最小试采样本

先采三条，每个构念一条，并有意覆盖 A/B 两种变体：

| 顺序 | 构念 | 任务 | 变体 | 重点观察 |
| --- | --- | --- | --- | --- |
| 1 | T3 | 窗口排队上限 | B | 私有标准、审核 JSON 和最终采用是否易懂 |
| 2 | I1 | 泊位占用报告 | A | 可信来源与状态版本是否能在角色间正确传播 |
| 3 | L1 | 三钩吊装吨位登记 | B | 中断、检查点、协调和接替是否自然 |

建议先让 2–3 人完成认知试采；若只测试页面，可由一人分饰角色，但必须选择“单人试采”，且数据不得升级为正式 Human Reference。

## 4. 每条轨迹的现场检查

保存前：

- [ ] 已说明试采用途、数据范围和退出方式，并确认知情同意；
- [ ] 团队代号、会话代号和参与者代号均为匿名编码；
- [ ] 三人模式下三个角色由不同代号承担；
- [ ] 每名参与者只看到其角色允许看到的信息；
- [ ] 参与者没有查看同一道题的另一变体；
- [ ] 所有必填输出非空，JSON 字段结构有效；
- [ ] 页面刷新、角色串看、主持人提示等异常已写入协议偏离记录。

保存后：

- [ ] 页面进度增加 1，目标槽位显示“已采集并锁定”；
- [ ] 再次提交同一槽位返回 `409 slot_already_collected`；
- [ ] `/api/status` 的 Human 数量同步增加；
- [ ] 匿名池增加一条 `trace-xxxxxxxxxxxx`，ID 和页面内容均不含 Human/Agent 来源；
- [ ] 匿名页面不显示团队、会话、参与者代号、模型名、功能分或内部路径；
- [ ] 服务重启后已采数量不回退，已采槽位不被空模板覆盖。

## 5. 量表试评

至少让一名未参与轨迹执行的人对三条试采 Human Trace和三条随机 Agent Trace完成评分，并检查：

- [ ] 评委不能从 ID 或页面字段判断来源；
- [ ] 切换刺激后，上一条刺激的单选项全部清空；
- [ ] 12 项必须全部为 1–7 的整数才能提交；
- [ ] 评委代号不接受姓名式自由文本，只使用预先分配的匿名代号；
- [ ] 同一评委对同一刺激重复提交返回 `409 duplicate_rating`；
- [ ] 备注只记录量表理解和页面问题，不含个人信息；
- [ ] 评分文件包含 `pilot: true`，`h1_formal_score` 为 `null`。

## 6. 认知访谈问题

每名参与者完成后用同一组问题访谈并按代号记录：

1. 哪一句角色说明最难理解？你当时认为自己能看到和不能看到什么？
2. 你如何判断何时把工作交给下一个角色？
3. JSON 字段中是否有含义相近、容易混淆或不知道该填什么的字段？
4. 任务变体改变后，哪部分要求最容易漏掉？
5. 页面是否诱导你查看其他角色的信息，或替其他角色完成工作？
6. 12 个量表项中哪些看起来重复，哪些无法只凭轨迹判断？
7. 完成一条轨迹和一条评分分别耗时多久？是否出现疲劳或机械作答？

## 7. 进入正式采集前的放行条件

满足以下条件后，才能新建正式输出目录并冻结正式版本：

- 三个构念各至少完成一条可解析试采，服务端无空提交和角色顺序错误；
- 无来源泄露、匿名代号泄露或槽位静默覆盖；
- 服务重启后 Registry、匿名池和已采数量一致；
- 参与者能够复述角色可见边界和交接规则；
- 评委能够区分“互动像不像真人”与“任务答案对不对”；
- 主要说明和量表问题已根据认知访谈修订并形成新冻结版本；
- 正式团队分配确保同一团队不接触同一道题的 A/B 两个变体；
- 正式分析方案预先登记刺激排布、评委分配、排除规则、缺失处理和 Human–Agent 比较方法。

若任何放行条件失败，保留试采证据和问题记录，修改后使用新的 pilot 版本重测；不得把失败试采清洗后冒充正式数据。
